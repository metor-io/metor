# Implementation plan — packs & functional authoring

Status: **design** (2026-07-11). Design: `docs/design-packs-authoring.md`. Summary of what
we build: a **`Pack`** seam (erased entries over one `Driver` trait) serving the static
registry, a new multi-system dl **ABI v5** (nine `fsw_pack_*` symbols, flag-day), and the
process-worker path; **functional authoring** (`system(fn)`/`.init(fn)`/`Pack::task`) via
Bevy-pattern handler traits; **sequence/system unification** (occupant tail as a mount
mode, `cycle().await`, the dropped-publish fix); and the wiring surface for all of it
(`artifact` without `type=`, entry-addressed `system` nodes, `allow … artifact=`).

Built in **six work packages**, each landing green with a commit at its boundary.
Dependency graph (strict edges →):

```
WP1 (read ergonomics) ── independent, land first
WP2 (handler + Pack, static path) ─▶ WP3 (ABI v5 + loader + wiring + workers, flag-day)
                                          ─▶ WP4 (unification) ─▶ WP5 (examples + docs)
WP6 (extras a–d, trim-able): a rides WP3's manifest field; b is independent;
                             c/d ride WP2's seam
```

Gates that stay green throughout: `cargo test -p metor-fsw-2` (including the dl/proc/slot
integration suites; `tests/proc_integration.rs` is `harness = false`), the
`examples/adcs-fsw2` test suite, clippy, and the trybuild suites once WP2 adds them.
WP3 onward adds a CLI smoke: `metor-fsw run mission.kdl --build`. End-to-end acceptance
(WP5): one `pack()` definition driving static, dlopen, and process modes with identical
mission behavior, and a slot loading a plain cyclic occupant.

**Files:** `src/port.rs`, `src/message.rs`, a few example call sites.

> **Status: LANDED** — the framework halves shipped with unit tests: `FrameGrant`'s
> `Deref` (`src/port.rs:422-436`) and `MsgIn::try_next`/`drain_iter`
> (`src/message.rs:375`, `:392`). Example call sites convert with the WP5 rewrite.

- `impl Deref<Target = F> for FrameGrant` (`src/port.rs:365-420`) using the `&self`-tied
  lifetime (the `FrameGrant::get` shape) — `input.latest()` then `record.omega`, no
  `.get()`. **Not** on `Input` (a read advances the cursor; `deref` takes `&self`) and

  deref would silently shorten it). `.get()` stays for callers that want the long borrow.
- `MsgIn::try_next() -> Option<M>` and `drain_iter()` beside `drain`
  (`src/message.rs:321-392`), same id filtering.
- Convert a handful of example call sites; unit tests ride the same files.

## WP2 — handler machinery + `Pack`, static path only (no ABI change)

**Files:** new `src/handler/{mod,param,tuples}.rs`, new `src/pack.rs`;
`src/wiring/mod.rs` (registry), `src/coordinator/mod.rs` (`DriverSlot`).

- `ExecParam` (State / `Item<'r>` / decl / bind / get) with impls for `&mut Input<F>`,
  `&mut MsgIn<M>`, `&mut Output<F>`, `&mut MsgOut<M>`/`&mut CommandOut<M>`, `Timestamp`,
  `&mut HealthPort`; decl + bind generated by **one** `macro_rules!` tuple walk so
  descriptor order and bind order cannot drift (design §4.1).
- `ExecuteFn<S, Marker>` / `InitFn<S, Marker>` (arities 0..=16, double-`FnMut` bound),
  `#[diagnostic::on_unimplemented]` on every handler trait, trybuild UI tests (pass set +
  one failure per diagnostic).
- `TaskParam` (by-value: `Input<F>`, `Output<F>`, `MsgIn<M>`, `MsgOut<M>`,
  `CommandOut<M>`, `Seq`, `Params<P>`) + `AsyncSystemFn` over `FnOnce(..) -> Fut`,
  `IntoOutcome` for `Outcome` and `()`.
- `Pack`/`PackEntry { name, descriptor, params_schema, params_default, reloadable, make }`
  with `make: Box<dyn FnMut(EntryParams, &mut AnySource, Mount) -> Result<Box<dyn Driver>,
  MakeError>>`; `AnySource { Host(Binder), Raw(RawBinder) }`; descriptors computed from
  param types at `.system()` (no instance constructed); `.state(prebuilt)` stored as
  `Option<S>` with `reloadable: false`.
- `FnDriver` (owns S + `P::State` + the health/log tail bound last, mirroring `Out::bind`
  order `src/system/mod.rs:172-177`; step mirrors `CyclicRunner::step`,
  `src/system/mod.rs:371-384`) and a minimal `FutureDriver` (Wired form only; occupant
  form is WP4).
- `Registry::register_pack`: widen `SystemFactory` from the plain `fn` pointer
  (`src/wiring/mod.rs:126`) to `Box<dyn FnMut>` so a factory can own its pack entry;
  `CoordinatorBuilder` gains the pack-entry registration arm + the `DriverSlot` adapter
  over `CyclicSlot` (`src/coordinator/mod.rs:535`).
- **Tests:** the decl/bind-order property test (a counting `RingSource`: decls per
  direction == rings consumed, for fn, task, and `system_type` entries); a shared-`Rc`
  two-entry smoke test through a static coordinator (both entries observe one mutation);
  a KDL mission resolving via `register_pack`; trybuild suites.

## WP4 — unification: `cycle().await`, general occupants, counter fix

**Files:** `src/sequence/mod.rs`, `src/pack.rs` (occupant-mode `FutureDriver`),
`src/coordinator/{mod,slot}.rs`, `src/port.rs`/`src/message.rs` (`Drops`),
`macros/src/sequence.rs`.

- `SeqClock` → `CycleClock` (old name re-exported); `pub fn cycle() -> NextCycle`
  capturing `armed_at = clock.now`, `Ready(now)` when `clock.now > armed_at` — no waker,
  re-polled every cycle, deterministic under a simulated clock, the same shape as `Wait`
  (`src/sequence/mod.rs:159-172`). No auto-abort; the documented idiom is
  `if aborted() { return }` after each await.
- Occupant tail becomes a **mount mode**: one shared `pub(crate) fn occupant_tail()`
  (`SlotControlIn` input; `SequenceStatus` + health + log outputs) consumed by (a) host
  `add_slot` contract derivation (`src/coordinator/mod.rs:1155-1167`), (b) the pack
  driver's occupant-mode bind — order: user inputs → `SlotControlIn` → user outputs →
  `SequenceStatus` → health → log, today's `SeqSystem::build` order
  (`src/sequence/mod.rs:343-358`) — and (c) the worker. Slots accept **any** entry; sync
  occupants get stop-on-cancel → `Done(Aborted)`. `SeqSystem`/`SeqBound`/`SeqState`
  absorbed into the occupant-mode `FutureDriver`.
- Dropped-publish fix, closing the TODO at `src/sequence/mod.rs:326-332`:
  `enum Drops { Local(u64), Shared(Rc<Cell<u64>>) }` replacing `dropped: u64` on
  `Output`/`MsgOut` (`src/port.rs:95-97`) — only the failure arm and `take_dropped` touch
  it; `FutureDriver`'s `TaskParam::bind` runs under a `BindCx` carrying the shared cell;
  per step a nonzero sum folds into `health.error("publish_dropped")`.
- `#[sequence]` deprecated to an fn-passthrough + note pointing at `Pack::task`.
- **Tests:** a cyclic occupant in a slot (load/start/cancel → `Done(Aborted)`); an async
  non-sequence occupant; dropped-publish surfaced through a future-owned output;
  `cycle().await` determinism under a simulated clock (same tick sequence across runs);
  the abort latch across `cycle()` awaits.

## Risks / decisions to watch

- **R1 — bind-order drift.** Three binders, one order. The single tuple walk and the
  single `occupant_tail()` make it structural; WP2's counting-source property test is the
  regression tripwire and must cover every entry shape (fn, task, `system_type`, both
  mounts).
- **R2 — the WP3 flag day.** Everything rebuilds in one train (framework, macros,
  fixtures, examples); nothing external consumes the ABI (`publish = false`), and stale
  artifacts fail closed on the version word. Keep WP3 to one commit that the CLI smoke
  gates.
- **R3 — `pack()` purity.** Describe calls `pack()`; if an author does real work there
  (opens sockets at pack construction rather than in init closures), describe acquires
  resources. Document the contract ("registration only; effects belong in init/make"),
  and note that `fsw_pack_open` catching a panic → null keeps a violent violation clean.
- **R4 — closure inference.** The HRTB double-bound is Bevy-proven for free fns; closures
  may need annotations. trybuild pins the *messages* so a rustc bump that regresses the
  diagnostics is caught, not just compilation.
- **R5 — shared-state teardown.** Entry states alias the pack's shared `Rc`/`Arc`; the
  `Arc<PackLib>` chain enforces destroy-before-close, and the WP3 drop-order test proves
  it with canaries rather than trusting declaration order by eye.
- **R6 — `CyclicSlot` regressions.** WP4 rehomes a shipped, tested path (`run_seq_*` →
  `FutureDriver`). Land the pure factoring first, gated on the existing slot/sequence
  suites, before the new occupant kinds ride on top (the `SeqWorker` precedent,
  `docs/process-slots-plan.md` W3/R6).
