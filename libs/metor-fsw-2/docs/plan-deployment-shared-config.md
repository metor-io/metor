# Plan: deployments, shared configuration

Implements [design-deployment-shared-config.md](design-deployment-shared-config.md).
Seven work packages. Each ends with a green tree. Paths are relative to
`libs/metor-fsw-2` unless they start with `examples/` or `libs/`.

Test commands used throughout:

```sh
cargo test -p metor-fsw-2                       # Rust unit + integration
cargo clippy -p metor-fsw-2 --all-targets       # lints, house rule
cargo check -p metor-panel                      # Wiring consumer compiles
cargo test -p adcs-fsw2                         # example targets (skip w/o python3)
(cd python && python3 -m unittest discover -s tests)
```

## Sequencing

```text
WP1 ─> WP2 ─┬─> WP3 ─> WP4 ─┐
            └─> WP5 ─> WP6 ─┴─> WP7
```

WP1 and WP2 are strictly sequential and must land before anything else. After
WP2 the two branches are independent: WP3/WP4 touch the Python emitter,
`py.rs`'s embedded list, fixtures, and `tests/`; WP5/WP6 touch `cli.rs`,
`build_driver.rs`, and `program.rs`. WP7 waits for both.

## Deviations from the design doc

Found while grounding the plan; each is small and noted at the package.

1. `validate_deployment` runs inside `ingest_ir` (`src/wiring/py.rs`), not in
   the CLI after ingestion. Ingest is the one boundary where an untrusted
   document enters, and the example tests call the evaluator without the
   CLI; one gate there, then trust.
2. `eval_python_target` becomes `eval_python_deployment` returning
   `Deployment`. Five example tests under `examples/adcs-fsw2/tests/` call
   it and take `.target(None)`. `target.py` itself is untouched.
3. `python/tests/data/demo.py` is generated by `write_demo_fixture`
   (`src/wiring/pack_module.rs:693`), so the pyright coverage for
   `Deployment` goes in a new hand-written `python/tests/data/deployment.py`
   added to the pyright invocation.
4. `RunArgs::target`, `BuildArgs::target`, and `PackageArgs::target` are the
   positional *path* today. They rename to `path` so `--target <NS>` can be
   the `target` field. The `RunArgs` literal in `cli.rs`'s tests changes
   with it.
5. `print_preflight(&Wiring, &Path)` keeps its signature; the member's
   namespace is in `wiring.coordinator.namespace`.

## WP1: `Deployment` type and validation (Rust only)

Files:

- `src/ir.rs`: bump `IR_VERSION` to 10. Add
  `pub struct Deployment { pub ir_version: u32, pub targets: Vec<Wiring> }`
  with serde derives, `path_stripped()`, and
  `pub fn target(&self, namespace: Option<&str>) -> Result<&Wiring, LoadError>`
  implementing the four selection arms from the design.
- `src/wiring/error.rs`: add `LoadError::TargetRequired { available: Vec<String> }`,
  `UnknownTarget { requested: String, available: Vec<String> }`,
  `NamespaceRequired { index: usize }`, `DuplicateNamespace { namespace: String }`,
  `NamespaceOverlap { outer: String, inner: String }`, and
  `EmptyDeployment`. Messages spell the available namespaces comma-separated,
  matching the design's error text.
- `src/wiring/validate.rs`: add `pub(crate) fn validate_deployment(&Deployment)`:
  envelope version (reuse the `IrVersionMismatch` variant), non-empty, and
  with more than one member: every namespace present, unique, and not a
  dotted prefix of another. Do not run per-member `validate` here; resolve
  does that on the selected member.
- `src/wiring/mod.rs`: re-export `Deployment` from `model`, and
  `validate_deployment` as `pub` beside `resolve`, so a Rust-built envelope
  can pass the same gate ingest applies in WP2.
- `tests/ir_contract.rs`: an `envelope_round_trips` test wrapping two
  `maximal()` clones with distinct namespaces in a `Deployment` and
  round-tripping through JSON. Leave `golden_fixture_round_trips` alone; it
  does not read the version.

Tests to add: `validate_deployment` unit tests in `src/wiring/validate.rs`'s
test module (or a sibling `tests` file if one exists): version skew, empty,
one member without namespace passes, two members with one missing fails,
duplicate, `sat`/`sat.plant` overlap, `fleet.sat1`/`fleet.sat2` passes.
`Deployment::target` unit tests: the four arms plus the single-member
namespace mismatch.

What could go wrong: `LoadError` is `miette::Diagnostic`; the new variants
are spanless like `IrVersionMismatch` and must say so. Nothing else changes
behaviour because nothing produces a `Deployment` yet.

Green when:

```sh
cargo test -p metor-fsw-2 --lib wiring::validate
cargo test -p metor-fsw-2 --test ir_contract
cargo test -p metor-fsw-2 && cargo clippy -p metor-fsw-2 --all-targets
```

## WP2: envelope on the wire, both sides, degenerate selection

The atomic boundary: the recorder emits the envelope, ingest reads it, and
every caller takes the only member. Cannot be split further and stay green,
because `tests/py_eval.rs` runs the embedded recorder through ingest.

Files:

- `python/metor-config/metor_config/_version.py`: `IR_VERSION = 10`,
  `__version__ = "0.4.1"`.
- `python/metor-config/pyproject.toml`: `version = "0.4.1"`.
- `python/metor-config/metor_config/_target.py`: `to_ir()` keeps returning
  the member `Wiring` dict (drop `metor_config_version` from it). Add a
  module-level `_envelope(targets: list[Target]) -> dict` producing
  `{ir_version, metor_config_version, targets: [t.to_ir() …]}`. `emit()`
  and `_emit_at_exit` write `_envelope([the one target])`. `_the_target()`
  stays for now (WP3 removes it).
- `src/wiring/py.rs`: rename `eval_python_target` to
  `eval_python_deployment -> miette::Result<Deployment>`. `ingest_ir` reads
  `ir_version` off the raw `serde_json::Value` first and returns the
  `IrVersionMismatch` message on skew, then deserializes `Deployment`, then
  `validate_deployment` (deviation 1). Update the module doc's first
  paragraph.
- `src/wiring/mod.rs`: `pub use py::eval_python_deployment;` update the
  module doc line naming the old function.
- `src/cli.rs`: `load_source -> miette::Result<Deployment>`. In `cmd_build`,
  `cmd_package`, `cmd_check_ir`, and `load_run_wiring`, take
  `deployment.target(None).into_diagnostic()?` and clone the member. This is
  the degenerate path only; `--target` arrives in WP5.
- `tests/py_eval.rs`: call `eval_python_deployment`, then
  `.target(None).unwrap()` before the existing assertions; add one assertion
  that the envelope has exactly one member.
- `tests/golden/target.json`: the `sed` above.
- `examples/adcs-fsw2/tests/{bundle,momentum,eclipse,closed_loop,sequences}.rs`:
  `eval_python_target(&p)` becomes `eval_python_deployment(&p)` followed by
  `.and_then(|d| d.target(None).cloned().into_diagnostic())` or the
  equivalent match arm each file already has; five call sites, one per file
  except `sequences.rs` which has two (lines 60 and 380).
- `python/tests/test_golden.py`: `test_emits_the_golden_fixture` compares
  `build_target().to_ir()` as today (the member), and adds one assertion
  that `mc._target._envelope([t])["targets"][0]` equals it and the envelope
  carries `IR_VERSION`.

What could go wrong: the `metor_config_version` move. The golden normalizer
already pops it, and `Wiring` is not `deny_unknown_fields`, so an extra key
either way is harmless; still, put it on the envelope only so the goldens
stay honest. `cargo test -p adcs-fsw2` needs the example venv stubs and
skips otherwise; run it anyway to catch the compile. The panel imports
`Wiring` only; `cargo check -p metor-panel` proves nothing moved under it.

Green when:

```sh
cargo test -p metor-fsw-2 && cargo clippy -p metor-fsw-2 --all-targets
cargo check -p metor-panel
cargo test -p adcs-fsw2
(cd python && python3 -m unittest discover -s tests)
```

## WP3: the Python `Deployment` builder

Files:

- `python/metor-config/metor_config/_deployment.py` (new): `class
  Deployment` with `targets: list[Target]`; constructor appends to a
  module-level `_deployments` list, rejects a non-`Target` member, a member
  already in another deployment, and a second `Deployment`. Method `to_ir()`
  returns the envelope (move `_envelope` here from `_target.py`).
- `python/metor-config/metor_config/_target.py`: emission rule becomes: one
  `Deployment` constructed, emit it; else exactly one `Target`, emit
  `Deployment(targets=[it])`; else `RuntimeError` with the count. `emit()`
  accepts `Deployment | Target | None`. Delete `_the_target`. In
  `_add_expr`, set `entry["target"] = self`; in `_program_ir`, include a
  system entry only when `entry["target"] is self`, and move the
  never-added warning to deployment emission so it fires once. In `add` and
  `slot`, call `spec._bind(self)` before `_param_source()`.
- `python/metor-config/metor_config/_model.py`: `Spec._bind(self, target)`,
  a no-op with a one-line doc.
- `python/metor-config/metor_config/_builtins.py`: move `Presets` here
  beside `Alarms`. It returns a `Spec` subclass whose `_bind` renders
  `preset=[p.to_json(target.namespace) …]` into `self.params`. Its
  docstring drops the "the `Target` must exist first" sentence.
- `python/metor-config/metor_config/__init__.py`: export `Deployment`; import
  `Presets` from `_builtins`; export `_deployments` for the tests beside
  `_targets`.
- `src/wiring/py.rs`: add `metor_config/_deployment.py` to
  `EMBEDDED_PACKAGE`. Forgetting this makes a venv-less `metor-fsw run` fail
  with `ModuleNotFoundError`, and `tests/py_eval.rs` runs venv-less.
- `python/tests/test_recorder.py`: `setUp` also clears `mc._deployments`.
  New tests: implicit one-member emission; two `Target`s and no
  `Deployment` raises with "found 2"; two `Deployment`s raise; one target in
  two deployments raises; two members each adding a `@system` emit disjoint
  `program.decls` while both carry the shared `Frame` class; never-added
  warning printed once; `Presets` added to a namespaced member qualifies
  with that namespace regardless of construction order; `Presets` on an
  un-namespaced member leaves references bare. Update
  `test_exactly_one_target_rule` for the new message and
  `test_presets_qualify_and_embed` for the moved import.
- `python/tests/data/deployment.py` (new, hand-written): a two-member file
  using `Deployment`, a generated `demo` entry, and `Presets`, for pyright.
- `python/tests/test_pyright.py`: add the new file to the pyright argument
  list.

What could go wrong: `test_golden.py`'s `setUp` clears `_targets` and
`_program`; it must clear `_deployments` too or the second test sees the
first's deployment. `Presets` moving modules changes `_source_ref` anchors
in no golden (the golden target has no presets). The pyright gate skips
without pyright on PATH; run it with `METOR_ENABLE_PYRIGHT=1` at least once.

Green when:

```sh
(cd python && python3 -m unittest discover -s tests)
(cd python && METOR_ENABLE_PYRIGHT=1 python3 -m unittest tests.test_pyright)
cargo test -p metor-fsw-2 --test py_eval
```

## WP5: `--target` selection, `--triple`, preflight, per-member build

Files:

- `src/cli.rs`:
  - `BuildArgs`, `PackageArgs`, `RunArgs`: positional field `target` →
    `path`; `triple` gets `long = "triple"`; new
    `#[arg(long = "target", value_name = "NS")] target: Option<String>`.
    Update the three doc comments and `merge_target`'s comment.
  - `fn select<'a>(deployment: &'a Deployment, ns: Option<&str>) -> miette::Result<&'a Wiring>`,
    the one call into `Deployment::target` with `into_diagnostic`.
  - `cmd_run`: select, then the existing pipeline on the member. A bundle
    with `--target` set compares against `coordinator.namespace` and errors
    with the design's third message on mismatch.
  - `cmd_build`: no `--target` provisions every member in envelope order
    and prints a namespace header per member (blank header when the sole
    member has none); with `--target`, one member.
  - `cmd_package`: select (WP6 handles the multi-member `--check-ir`).
  - Rename `refresh_run_packs`/`load_run_wiring`/`provision_run_artifacts`'s
    `target: &Path` parameter to `path`; update the `RunArgs` literal in
    `refresh_run_packs_skips_and_noops`.
- `src/cli/ui.rs`: `print_preflight` renders `target.py · fsw` when
  `wiring.coordinator.namespace` is set, else the file name alone.
- `src/wiring/build_driver.rs`: `wasm_out_dir` joins the namespace as a
  subdirectory when present. `provision_program` (`src/wiring/program.rs`)
  already `create_dir_all`s the out dir, so nothing else changes.

Tests to add: in `src/cli.rs`'s test module, `select` over a two-member

one-member with and without namespace). In
`src/wiring/build_driver/tests.rs`, `wasm_out_dir` with and without a
namespace lands in `<profile>/<ns>/` vs `<profile>/`.

What could go wrong: clap rejects two args with `long = "target"` at
runtime, not compile time; the `Cli::command().debug_assert()` idiom in a
test catches it. `cargo test -p adcs-fsw2` does not use the CLI and is
unaffected. Scripts that passed `--target <TRIPLE>` to `build`/`package`
break by design; the docs update is WP7.
